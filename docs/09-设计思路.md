# 设计思路

## 千年营造·华夏砖木——中国古代建筑数据可视化平台

---

## 一、设计理念

### 1.1 核心思想

**"以数为媒，以艺载道"**

- **数据为本**：所有展示内容基于真实可信的数据源，确保科学性和准确性
- **艺术呈现**：采用符合古建筑美学特征的视觉设计，营造沉浸式体验
- **文化传承**：通过交互设计，引导用户深入了解古建筑背后的文化内涵

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **真实性** | 数据来源权威可溯，不虚构、不夸大 |
| **完整性** | 覆盖建筑成就、科学家、著作、文化四个维度 |
| **艺术性** | 视觉风格契合古建筑主题，色彩取自传统建筑元素 |
| **流畅性** | 页面过渡自然，交互反馈及时，加载性能优化 |
| **实用性** | 功能实用，操作简便，适配多种设备 |

## 三、视觉设计思路

### 3.1 色彩设计

色彩灵感来源于中国传统建筑元素：

| 色彩名称 | 色值 | 灵感来源 | 使用场景 |
|----------|------|----------|----------|
| **古铜金** | `#C8A96E` | 铜器、琉璃瓦 | 主色调、强调元素 |
| **青瓦色** | `#4ECDC4` | 青砖黛瓦 | 辅助色、图表配色 |
| **朱砂红** | `#E07B54` | 宫墙、门窗 | 点缀色、重要数据 |
| **深夜墨** | `#0d1117` | 夜空、墨汁 | 背景色 |
| **宣纸白** | `rgba(255,255,255,0.9)` | 宣纸 | 主要文字 |

**设计 rationale**：
- 深色背景营造沉浸式体验，突出数据主体
- 古铜金、青瓦色、朱砂红均取自传统建筑元素，增强文化认同感
- 高对比度确保数据可读性
- ECharts图表使用 `LinearGradient` 渐变色（古铜金→青瓦色等），增强视觉层次

### 3.2 字体设计

- **标题字体**：思源宋体（Noto Serif SC）—— 体现传统文化韵味
- **正文字体**：思源黑体（Noto Sans SC）—— 保证阅读清晰度
- **数字字体**：DIN Alternate —— 现代感与数据专业性

### 3.3 动效设计

**飘落叶片效果**：
- 替代传统的流星效果，更符合古建筑主题
- 四种叶片类型：银杏叶（秋）、枫叶（秋）、竹叶（春）、柳叶（春）
- 使用GSAP实现流畅的飘落动画，包含旋转和飘移

**页面过渡**：
- 标题淡入 + 图表面板依次入场（仅保留y轴位移动画，移除opacity避免echarts闪烁）
- 卡片悬停缩放 + 阴影效果 + 边框发光
- 数字滚动动画展示统计数据

**多层背景光晕**：
- 渐变装饰线增强面板层次感
- 卡片顶部渐变横线（hover时增强透明度）
- 脉冲呼吸动画点缀关键元素

## 四、数据可视化设计

### 4.1 图表选型原则

| 数据类型 | 选用图表 | 选型理由 |
|----------|----------|----------|
| 占比/分布 | 玫瑰图、饼图、环形图 | 直观展示各部分占比 |
| 时间序列 | 折线图、面积图、时间轴 | 展示演变趋势 |
| 地理分布 | 柱状图（按省份排名） | 展示空间分布特征 |
| 关系网络 | 力导向关系图 | 展示人物-作品-朝代关联 |
| 层级结构 | 旭日图 | 展示分类层级关系 |
| 多维对比 | 雷达图 | 对比多个维度的特征 |
| 关键词频次 | 柱状图（动态提取） | 从文本字段中提取分析维度 |
| 散点分布 | 散点图 | 展示两个连续变量之间的关系 |

### 4.2 动态数据分析工具

文化页面的图表并非直接映射原始数据，而是通过封装的工具函数从JSON中动态提取分析维度：

| 工具函数 | 功能 | 应用场景 |
|----------|------|----------|
| `countByField(detail, field)` | 按字段值统计频次 | 地区分布、材料统计、保护现状 |
| `extractKeywordFreq(detail, field, keywords)` | 从文本字段提取关键词命中次数 | 气候适应、文化内涵、技术特色 |
| `extractBuildingElements(detail, field)` | 从名称数组提取建筑元素词频 | 主要建筑元素、核心建筑类型 |
| `extractDynastyDist(detail)` | 从朝代字段提取朝代分组分布 | 历代分布 |
| `extractNumberFromText(detail, field)` | 从文本提取数字 | 全国遗存数量 |
| `countArrayField(detail, field)` | 从数组字段统计元素频次 | 多值字段统计 |

### 4.3 交互设计

- **悬停提示**：鼠标悬停显示详细数据，ECharts tooltip自定义样式匹配主题
- **点击下钻**：点击图表元素展开详情弹窗，展示建筑/人物/著作的完整信息
  - **朝代筛选联动**：首页和各子页面均支持六大朝代（先秦/秦汉/魏晋/隋唐/宋元/明清）多选筛选，通过按钮组实现，无需页面跳转即可切换数据；点击"返回首页"保留筛选状态

- **标签切换**：建筑文化页支持四类建筑切换，采用懒加载策略，首次切换时才初始化对应图表
- **数据洞察面板**：各子页面底部配置分析结论与关键词标签，帮助用户理解数据背后的规律
- **页面过渡**：平滑的页面切换动画，图表面板从下方依次滑入

## 五、响应式设计

### 5.1 断点设计

| 断点 | 设备 | 网格列数 | 特点 |
|------|------|---------|------|
| <375px | 小屏手机 | 1列 | 简化布局 |
| 375-767px | 手机 | 2列 | 统计/导航2列 |
| 768-1023px | 平板 | 2列 | 标准平板布局 |
| 1024-1439px | 小桌面 | 3列 | 标准桌面 |
| >=1440px | 大桌面 | 3列 | 最大宽度1920px |

### 5.2 适配策略

- 使用flexible.js实现rem自适应（1rem=100px@1920px），覆盖1080P~4K全场景
- 移动端禁用复杂动画，减少叶片数量
- ECharts配置自动适配（字体大小、标签旋转、图例位置）
- CSS Grid结合媒体查询实现多设备网格列数自动调整
- 支持减少动画偏好 `prefers-reduced-motion`
- 建筑文化页tab在移动端优化为垂直堆叠布局

## 六、创新点

### 6.1 内容创新

1. **多维度整合**：从"成就-人物-文献-文化"四大维度系统梳理中国古代建筑，涵盖115处古建筑、5位科学家、6部著作、38类文化形态
2. **数据驱动**：基于真实权威数据，所有图表数据从JSON动态加载，无硬编码内容
3. **文化传承**：不仅展示数据，更注重文化内涵的传递，数据洞察面板将可视化升华为数据叙事
4. **四类建筑深挖**：民居、官府、皇宫、桥梁四类建筑各配备6个主题图表，全方位展示建筑文化

### 6.2 技术创新

1. **主题化动效**：飘落叶片替代传统粒子效果，契合古建筑主题
2. **响应式适配**：基于flexible.js的rem自适应方案，覆盖1080P~4K全场景
3. **性能优化**：移动端自动降级复杂动画；tab懒加载避免首屏渲染压力；`setOption` notMerge=false避免清空重绘
4. **时序优化**：分离GSAP动画与ECharts渲染时序，移除opacity动画竞争，确保图表稳定渲染
5. **状态保持**：URL参数驱动朝代筛选联动，页面间无缝传递状态
6. **动态数据分析**：封装通用工具函数，从原始JSON数据动态提取关键词频次、建筑元素、朝代分布等分析维度，确保图表内容真实有分析意义

### 6.3 设计创新

1. **色彩体系**：从传统建筑中提取色彩（古铜金、青瓦色、朱砂红），营造沉浸式体验
2. **视觉层次**：深色背景 + 亮色图表，突出数据主体；渐变装饰线增强面板层次感
3. **动效节奏**：动画时长和缓动函数精心设计，避免视觉疲劳；位移动画替代opacity动画，消除echarts闪烁
4. **数据洞察**：各子页面底部配置分析结论面板，将数据可视化升华为数据叙事

## 七、设计重点与难点

### 7.1 设计重点

1. **数据真实性**：确保所有数据来源权威、可溯源。建筑成就数据源自国家文物局全国重点文物保护单位名录（**115条**，含桥梁8条、皇宫3条、官府4条、民居6条、城址4条、寺庙2条），科学家与著作数据来自百度百科等权威平台
2. **视觉一致性**：保持整体视觉风格的统一性，从传统建筑元素中提取色彩体系（古铜金、青瓦色、朱砂红），所有图表tooltip、legend样式统一主题化
3. **用户体验**：平衡信息密度与可读性，所有图表支持悬停提示和点击下钻查看详情；各子页面底部配置数据洞察面板，提供分析结论
4. **性能优化**：保证在各种设备上的流畅运行，echarts按需初始化（建筑文化页tab懒加载），避免一次性渲染过多图表；`setOption`使用`notMerge=false`避免清空重绘导致的闪烁
5. **跨页面联动**：实现朝代筛选状态在首页与子页面间的无缝传递，URL参数驱动数据过滤，返回首页时筛选状态不丢失

### 7.2 技术难点

1. **数据获取与整合**：古建筑数据分散在国家文物局、百度百科、中国非遗网等多个平台，需要编写爬虫脚本统一采集，并进行数据清洗和结构化处理
2. **图表自适应与闪烁问题**：ECharts在容器尺寸不稳定时初始化会导致图表先显示后消失再显示的闪烁现象；tab切换时非活动标签页的图表在`display:none`容器中初始化尺寸为0，导致渲染失败
3. **跨页面状态保持**：用户从首页选择朝代筛选后进入子页面，返回首页时需要保留筛选状态，涉及URL参数传递和页面间通信
4. **动画与图表渲染的时序竞争**：GSAP入场动画（opacity从0到1）与ECharts初始化同时进行，导致canvas渲染异常，出现"显示→消失→显示"的闪烁现象
5. **响应式适配**：从1080P到4K的超宽屏适配，以及移动端的简化展示，需要精细的断点设计和动态配置调整
6. **文化页动态数据图表**：文化页的图表需从JSON数据中动态提取关键词频次、建筑元素统计等，而非简单的直接映射，需要编写通用的数据分析工具函数（`extractKeywordFreq`、`extractBuildingElements`、`extractDynastyDist`等）

### 7.3 解决方案

| 难点 | 解决方案 |
|------|----------|
| 数据获取 | 编写4个Python爬虫脚本，从国家文物局、百度百科等权威来源获取；提供数据清洗脚本完成去重、校验、格式化 |
| 图表闪烁 | 移除GSAP的opacity动画（保留位移动画），避免echarts在opacity变化过程中重绘；`setOption`使用`notMerge=false`避免清空重绘；tab页面采用懒加载策略，首次切换时才初始化图表；移除`visibility:hidden`与`display:none`的叠加使用 |
| 跨页面状态 | 首页通过URL参数`?dynasty=xxx`传递筛选状态；子页面通过内联脚本动态重写返回链接，保留dynasty参数；各子页面读取URL参数并过滤对应数据 |
| 动画时序 | `pageEnterAnimation()`中`.chart-panel`只保留`y:20`位移动画，移除`opacity:0`淡入动画，确保echarts从初始化到渲染全程可见 |
| 响应式适配 | 使用flexible.js实现rem自适应（1rem=100px@1920px），覆盖1080P~4K；CSS Grid结合5个媒体查询断点实现多设备适配 |
| 动态数据图表 | 封装通用工具函数（`countByField`、`extractKeywordFreq`、`extractBuildingElements`、`extractDynastyDist`、`extractNumberFromText`），从JSON原始数据中动态提取分析维度，确保图表内容基于真实数据而非硬编码 |
